# CLAUDE.md — правила для агентов, работающих в этой директории

Это live-контур ИИ-интервьюера — один из двух контуров системы (см. корневой
[docs/Архитектура и дизайн MVP.md](../docs/Архитектура%20и%20дизайн%20MVP.md), раздел 3,
и [README.md](README.md) этой директории). Batch-контур не реализован — не путать зоны
ответственности при правках.

Прежде чем менять код здесь — прочитай [README.md](README.md) целиком, он объясняет
архитектуру и решения. Этот файл — только жёсткие правила, не дублирует объяснения.

## Неотменяемые правила

1. **Граф — код, не LLM с тулами.** Весь control flow интервью (переход между вопросами,
   выбор адаптивного вопроса, чек-ины) — явный Python в `state_machine.py`
   (`LiveContourEngine`). Никогда не добавляй LLM function calling/tools для управления
   потоком диалога (`next_question`, `end_interview` и т.п.) — это осознанное решение
   (см. README, «Почему граф — код»), не пробел, который надо закрыть.

2. **LLM вызывается только через `LiveControlLLM.decide()`** и всегда возвращает
   `LiveControlDecision` (structured output, `schema.py`) — не свободный текст. Если
   нужна новая способность агента, расширяй эту типизированную схему, а не парси текст
   регулярками.

3. **Контекст LLM-вызова = только текущий вопрос.** `prompts.build_turn_prompt()` не
   должен получать текст/эталоны других вопросов вакансии, полную историю интервью или
   резюме кандидата — см. докстринг `prompts.py`. Если добавляешь `contradiction_check`
   или `resume_inspired` (сейчас сознательно не реализованы, см. `schema.GapType`) —
   это меняет данное правило осознанно и должно быть явно описано в README, а не тихо.

4. **Бюджеты и приоритеты — в коде, не в промпте.** Лимит чек-инов (1 подряд), лимит
   подсказок (1 на вопрос), общий адаптивный бюджет интервью — проверяются в
   `state_machine.py` (`_act_on_decision`/`_handle_gap`), не полагайся на то, что промпт
   «попросит» модель соблюдать лимит.

5. **`EventLog` — только на запись, вперёд.** `out/*.jsonl` — протокол событий, вход для
   будущего batch-контура. Не переписывай прошлые события задним числом, не меняй формат
   `EventType`/`Event` без обновления README (раздел «Протокол событий») — на этот формат
   будет полагаться код, которого ещё нет.

6. **`FakeLLM` должен оставаться синхронизирован с реальным контрактом.** Любое изменение
   `LiveControlDecision`/`SYSTEM_PROMPT` — обнови оба класса в `llm_client.py`
   (`ClaudeAgentSDKLiveControlLLM` и `FakeLLM`), иначе `scripts/simulate.py` и тесты
   молча разойдутся с реальным поведением.

7. **Модель для live-контура — `claude-haiku-4-5`, не `claude-opus-5`.** Это осознанное
   решение пользователя (латентность важнее intelligence-максимума при бюджете в единицы
   секунд), не «забытая настройка по умолчанию» — не меняй без явного запроса.

8. **Прод: LLM, STT и TTS через OpenRouter.** Self-hosted STT/TTS из
   `docker-compose.yml` сняты (на VPS нет GPU). Деплой пишет `LLM_PROVIDER=openrouter`,
   модель `google/gemini-2.5-flash` (`OPENROUTER_MODEL`). STT — `whisper-1`
   (`/audio/transcriptions`, `STT_LANGUAGE=ru`). TTS — `fish-audio/s1` (OpenAI-совместимый
   `POST /audio/speech`, не протокол Fish Speech `POST /v1/tts` и не
   `openai/gpt-audio-mini`). Запас TTS (не включать по умолчанию):
   `google/gemini-3.1-flash-tts-preview`, voice Kore, только pcm.
   Локально по-прежнему можно выбрать другой `LLM_PROVIDER` в `live-agent/.env`:
     - `mistral` — `MistralLiveControlLLM`, прямой REST к Mistral API. Пробовали и
       откатили: бесплатный ключ отдавал 429 на каждый вызов (нулевая квота).
     - `anthropic_api` — `AnthropicAPILiveControlLLM`, прямой Anthropic Messages API
       (сам api.anthropic.com или купленный прокси через `ANTHROPIC_BASE_URL`).
     - без `LLM_PROVIDER` / `claude_sdk` — Claude Agent SDK (`claude login`); в
       прод-образе CLI больше не ставится.

9. **Любое изменение `state_machine.py` — с тестом.** `tests/test_state_machine.py`
   называет тесты по конкретной ветке из раздела 2.3.1 архитектурного документа. Новая
   ветка/тип адаптивного вопроса — новый тест, а не только код. Перед тем как считать
   изменение готовым: `pytest tests/ -q`.

10. **Не выдавай желаемое за проверенное.** Полный голосовой цикл (VAD → STT → граф → TTS
    через реальный LiveKit + Docker + подписку) на момент написания этого файла проверен
    лишь частично — см. «Статус проверки» в README. Если что-то по-прежнему не
    прогонялось вживую — так и напиши, не переформулируй как «готово».
