# Data model (demo overlay for 006)

База сущностей 005 не меняется. Здесь только то, что добавляет вход, воронка и состояния экрана. Хранение: TypeScript-модули + `sessionStorage`. Базы данных нет.

## DemoRole

| Поле | Смысл |
|---|---|
| `id` | `recruiter` \| `expert` \| `manager` \| `candidate-dmitry` \| `candidate-nikita` \| `candidate-lida` |
| `title` | Подпись на карточке входа («Рекрутер», «Кандидат») |
| `personName` | Анна Ковалёва, Алексей С., Игорь Матвеев, Дмитрий Козлов, Никита Белов, Лидия Орлова |
| `homePath` | Куда вести после попапа |
| `onboarding` | `RoleOnboarding` |

Валидация: шесть ролей из spec FR-002. Нет поля почты и пароля.

## RoleOnboarding

| Поле | Смысл |
|---|---|
| `who` | Кто вы в этом демо, одно-два предложения |
| `willSee` | Что будет на следующем экране |
| `firstAction` | Одно первое действие |
| `continueLabel` | Глагол («Перейти к вакансиям») |
| `backLabel` | «Назад к ролям» |

Показ: только после выбора роли на входе, до `homePath`. Закрытие без continue не пишет выбранную роль.

## DemoSession

| Поле | Смысл |
|---|---|
| `roleId` | Выбранная роль или пусто |
| `onboardingSeenFor` | Не обязательно; попап можно показать снова при выборе с входа |

Тема (`data-theme`) остаётся отдельным ключом, как в 005.

## PipelineCard

Карточка на доске. Не путать с полным `Candidate` из 005.

| Поле | Смысл |
|---|---|
| `id` | Стабильный id |
| `name` | Имя на карточке |
| `stage` | `invited` \| `inProgress` \| `processing` \| `reportReady` \| `decided` |
| `stageLine` | Одна строка статуса стадии человеческим языком |
| `reportHref` | Есть только если `stage = reportReady` и это канонический кандидат |
| `decisionLabel` | Только для `decided` (человеческое решение) |
| `canonical` | true у Дмитрия, Никиты, Лидии |

Правила:

- В каждой стадии минимум одна карточка.
- Канонические трое: `canonical: true`, `stage: reportReady`, смыслы статусов как в 005.
- Ранние стадии MUST NOT иметь `reportHref` на полный технический отчёт.

## VacancyCounts (R1)

Поля `invited`, `inProgress`, `processing`, `reportReady`, `decided` показываются **словами стадий**, не строкой `2/1/3/0`.

## ScreenState

Общий контракт состояния экрана, не таблица БД.

| Состояние | Что видит человек |
|---|---|
| `loading` | Каркас того же макета + «Загружаю…» / статус действия |
| `ready` | Содержимое |
| `empty` | Заголовок, «в этом демо данных нет», следующее действие если есть |
| `error` | Что случилось, почему важно, куда идти (часто ко входу) |

Запрещено: первый кадр без заголовка и без одного из четырёх состояний.

## State transitions

```text
S1 выбор роли → попап (роль ещё не записана)
попап continue → DemoSession.roleId → homePath
попап back / close → S1
любой экран → «К выбору роли» → S1 (роль можно сбросить)

Канбан: карточка reportReady + canonical → R5
карточка invited / inProgress / processing → без R5
карточка decided → подпись решения, без смены канона 005
```
