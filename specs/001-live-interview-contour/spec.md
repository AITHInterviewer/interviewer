# Feature Specification: Live-контур интервью

**Feature Branch**: `001-live-interview-contour`

**Created**: 2026-09-03

**Status**: Implemented (retroactively documented — код в `live-agent/` написан до синхронизации с Speckit; см. «Синхронизация с кодом» ниже)

**Input**: `docs/Архитектура и дизайн MVP.md`, разделы 2.3, 2.3.1, 2.3.2, 3; `live-agent/README.md`, `live-agent/CLAUDE.md`

## Синхронизация с кодом

Этот spec описывает уже существующую реализацию в `live-agent/` (не новую работу). Создан
задним числом, чтобы `specs/` стал источником истины наравне с кодом (см.
[[constitution]] Principle II). При любой следующей правке `live-agent/` — сверяться и
обновлять этот файл, а не только README/CLAUDE.md.

Реализовано (`live-agent/src/ainterviewer/`):
- `state_machine.py` — граф `LiveContourEngine`, покрыт тестами (`tests/test_state_machine.py`, 7/7).
- `schema.py`, `events.py`, `prompts.py`, `llm_client.py` — контракты, протокол событий, промпты, клиент Claude Agent SDK + `FakeLLM`.
- `agent.py` — обвязка LiveKit Agents (STT/VAD/TTS), не прогонялась вживую с реальным микрофоном.

Не реализовано: `live_coding`-формат, `contradiction_check`/`resume_inspired` (нужны резюме и кросс-вопросная история — см. `schema.GapType`), корректное завершение LiveKit-job после `Phase.DONE`.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Кандидат проходит вопрос голосом и агент понимает, когда ответ закончен (Priority: P1)

Кандидат отвечает голосом на вопрос вакансии. Система транслирует голос агента (TTS),
слушает кандидата, на каждой паузе решает: дать продолжить, перейти к следующему вопросу,
уточнить чек-ином, или задать адаптивный вопрос — без нажатия кандидатом каких-либо кнопок
«далее».

**Why this priority**: это ядро live-контура — без реактивного цикла на паузах вся система
превращается в анкету с озвучкой, теряя основное УТП относительно существующих асинхронных
инструментов (см. архитектурный документ, раздел 9, п.1 — «говорю в стену»).

**Independent Test**: `python scripts/simulate.py` в `live-agent/` — прогоняет граф по
сценарию реплик без LiveKit/сети, показывает переходы состояний.

**Acceptance Scenarios**:

1. **Given** агент задал вопрос и кандидат делает короткую паузу в середине фразы, **When** VAD детектирует тишину, **Then** `LiveControlLLM.decide()` классифицирует её как `continue`, и агент не вмешивается (реализовано, `state_machine.py`, ветка `Listening → Listening`).
2. **Given** кандидат дал полный, недвусмысленный ответ, **When** пауза детектирована, **Then** граф переходит к следующему вопросу без подтверждения (`exhaustive` → `NextQuestion`).
3. **Given** ответ неоднозначен (непонятно, закончил ли кандидат) и чек-ин ещё не использован на этом вопросе, **When** пауза детектирована, **Then** агент задаёт короткий чек-ин один раз; повторная неоднозначность на этом же вопросе ведёт к переходу дальше без второго чек-ина (реализовано — лимит «1 чек-ин на вопрос» проверяется в коде, не в промпте, см. `live-agent/CLAUDE.md`, п.4).
4. **Given** обнаружен чёткий пробел (`gap`) и адаптивный бюджет интервью не исчерпан, **When** пауза детектирована, **Then** граф формулирует и задаёт адаптивный вопрос одного из реализованных типов (`clarification` / `leading_hint` / `drill_down`); при исчерпанном бюджете — переход к следующему вопросу.

---

### User Story 2 - Live-контур пишет протокол событий для будущего batch-контура (Priority: P1)

Каждое решение и реплика live-контура попадает в `EventLog` (`out/<interview_id>.jsonl`) —
единственная точка стыка с batch-контуром ([[002-batch-evaluation-contour]]).

**Why this priority**: без протокола batch-контур не имеет входных данных — это блокер
для всей второй половины продукта (оценка кандидата).

**Independent Test**: запустить `scripts/simulate.py`, проверить, что `out/<id>.jsonl`
содержит валидные построчные JSON-события ожидаемых типов.

**Acceptance Scenarios**:

1. **Given** интервью стартовало, **When** любое событие происходит (вопрос задан, реплика кандидата, решение live-control, адаптивный вопрос, чек-ин, вопрос завершён), **Then** оно дописывается в JSONL-файл, файл не переписывается задним числом (реализовано, `events.py`).

---

### User Story 3 - Мгновенная реакция на паузу без ощущения зависания (Priority: P2)

Пока идёт LLM-решение (единицы секунд), кандидат слышит мгновенный бэкчаннел («Ага»,
«Понял»), а не тишину/спиннер.

**Why this priority**: снижает воспринимаемую задержку без ускорения самого LLM-вызова —
дешёвый UX-фикс поверх реального ограничения латентности.

**Independent Test**: в `agent.py` проверить вызов `backchannel_phrase()` — заготовленный
TTS-клип, без LLM, задержка ~0.

**Acceptance Scenarios**:

1. **Given** кандидат закончил произносить реплику, **When** VAD детектирует паузу, **Then** бэкчаннел звучит немедленно, до завершения `LiveControlLLM.decide()` (реализовано).

### Edge Cases

- LLM-вызов не укладывается в бюджет единиц секунд → открытый вопрос, см. [[constitution]] и раздел 10 архитектурного документа (не решено ни в коде, ни здесь).
- `live_coding`-формат — вне скоупа этого фича-файла (см. раздел 8 архитектурного документа, «Вне скоупа MVP» частично снят для `live_coding`, но код его не реализует).
- Резюме кандидата и кросс-вопросная история намеренно не передаются в контекст (см. `live-agent/CLAUDE.md`, правило 3) — `contradiction_check`/`resume_inspired` не могут сработать в текущей реализации.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Live-контур MUST классифицировать каждую паузу кандидата на один из четырёх классов: продолжение, исчерпывающий ответ, неоднозначность, чёткий пробел (реализовано, `Decision` в `schema.py`).
- **FR-002**: Live-контур MUST ограничивать чек-ины одним подряд на вопрос (реализовано, код, не промпт).
- **FR-003**: Live-контур MUST ограничивать адаптивные вопросы общим бюджетом интервью 3–4 (реализовано; типы `contradiction_check`/`resume_inspired` из бюджета архитектурного документа в коде не реализованы — фактический набор триггеров уже уже, см. `schema.GapType`).
- **FR-004**: Live-контур MUST писать каждое событие в протокол `out/<interview_id>.jsonl` без изменения прошлых записей (реализовано).
- **FR-005**: Live-контур MUST держать контекст LLM-вызова ограниченным текущим вопросом — без резюме, других вопросов вакансии, полной истории интервью (реализовано, осознанное ограничение — см. `live-agent/CLAUDE.md`, правило 3).
- **FR-006**: Live-контур MUST использовать `claude-haiku-4-5` с `tools=[]`, `max_turns=1` для классификации/формулировки — не function calling (реализовано, осознанное решение, не менять без явного запроса пользователя).
- **FR-007**: Live-контур NOT MUST реализовывать `live_coding`, `contradiction_check`, `resume_inspired` в текущей итерации — явно отложено.

### Key Entities

- **QuestionRunState** — контекст одного вопроса: список реплик кандидата по этому вопросу, счётчики использованных чек-инов/подсказок; полностью сбрасывается при переходе к следующему вопросу.
- **LiveControlDecision** — структурированный выход LLM: класс паузы + (опционально) текст следующей реплики/адаптивного вопроса.
- **Event** — одна запись протокола (см. `live-agent/README.md`, «Протокол событий», список типов).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Граф проходит `pytest tests/ -q` в `live-agent/` без падений — регрессия по каждой ветке из раздела 2.3.1 архитектурного документа (текущее состояние: 7/7 зелёных).
- **SC-002**: `scripts/simulate.py --real` проходит полный сценарий вопросов вакансии с реальным Claude Agent SDK без обращения к незадействованным веткам (`contradiction_check`/`resume_inspired`/`live_coding`).
- **SC-003**: Полный голосовой цикл (реальный микрофон → VAD → STT → граф → TTS → динамики) проходит вживую хотя бы один раз — на момент создания этого файла НЕ выполнено (см. `live-agent/README.md`, «Что дальше»).

## Assumptions

- STT/TTS — self-hosted через Docker (faster-whisper-server, speaches.ai/Piper), не облачные API — зафиксировано в `live-agent/CLAUDE.md`, не предмет обсуждения в рамках этого спека.
- LiveKit Agents закрывает AEC/VAD/turn-taking из коробки — не переизобретаем.
- SC-003 (живой голосовой прогон) остаётся открытым пунктом до отдельной проверки; этот спек не блокируется на нём, так как граф протестирован изолированно.
