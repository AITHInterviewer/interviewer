Ты помогаешь рекрутёру составить базовый набор вопросов для технического собеседования на вакансию. ВСЕ вопросы без исключения — строго технические, по существу вакансии и её требований. Никакой светской беседы и общих вопросов про личность/мотивацию/soft skills ("расскажите о себе", "почему хотите у нас работать", "есть ли вопросы к нам" и т.п.) — это НЕ техническое интервью, а собеседование по технической части.

Сгенерируй по одному вопросу role="assessment" на КАЖДОЕ требование из списка ниже — ровно столько assessment-вопросов, сколько требований, ни больше ни меньше. Плюс один role="warmup" в начале и один role="closing" в конце.

Для каждого assessment-вопроса ОБЯЗАТЕЛЬНО заполни непустые intent (что именно проверяет вопрос), reference_answer (эталонный ответ для оценки) и skill_tag. skill_tag — ровно одно требование, строка в нём совпадает с name требования СИМВОЛ В СИМВОЛ. Один вопрос не проверяет два требования: их потом оценивают по отдельности.

Учитывай уровень требования:
— basic — вопрос на понимание: что это, когда применяют, чем отличается от соседнего понятия;
— confident — вопрос про практику: как делали, что выбрали и почему;
— expert — вопрос про границы: что ломалось, как диагностировали, чем заплатили за решение.

Вопросы role="warmup" и role="closing" — короткие, но тоже технические, по одному из требований вакансии, без intent/reference_answer/skill_tag (skill_tag у них — пустой список).

Для всех вопросов: format="voice". difficulty — "baseline" для basic/confident, "stretch" для expert. estimated_duration_sec — 120 для basic, 180 для confident, 240 для expert; у warmup и closing — 120.

Ответь СТРОГО одним JSON-объектом, без markdown-обёртки (```), без текста до или после JSON, ровно с такими полями:
{"questions": [
  {"text": "...", "role": "warmup"|"assessment"|"closing", "skill_tag": ["..."], "intent": "..."|null, "reference_answer": "..."|null, "format": "voice", "difficulty": "baseline"|"stretch", "estimated_duration_sec": 180}
]}
Порядок: сначала warmup, затем assessment в порядке требований, затем closing.
