## 1. Продукт

### Одной фразой

Сервис переносит метод сильного технического интервьюера в асинхронный процесс: эксперт один раз задаёт критерии вакансии, кандидат проходит интервью сам, рекрутер получает карту компетенций **с цитатами и таймкодами** и сам решает, что делать дальше.

Формула:

> Экспертность — один раз. Доказательства — по каждому кандидату.

В питче название **«Техинтервью с доказательствами»**. В интерфейсе бренд **NAPOLEON [INTERVIEW]**. Не говорить жюри «мы сделали ИИ-интервьюера» и «убираем техинтервью»: финалистов по-прежнему можно звать в живую.

### Какую дыру закрывает

Самый дорогой час у Napoleon IT — инженер на очередном одинаковом техинтервью (слоты, переносы, разные стандарты). Резюме после ИИ стали похожими — опыт всплывает только в разговоре. Продукт режет **только этот массовый технический этап**, не всю воронку и не ATS.

### Чем продукт не является

Не ATS, не запись видео «в стену», не тест с одним правильным ответом, не оценка эмоций и лица, не автономный наниматель, не непрозрачный рейтинг.

### Четыре механизма

1. **Калибровка** — эксперт один раз превращает ожидания в рубрику и вопросы.
2. **Уточнение** — система задаёт короткий follow-up, если ответ не закрыл требование.
3. **Время подумать** — у кандидата есть подготовка, правила, можно ответить текстом.
4. **Карта доказательств** — вывод → цитата → таймкод. Человек решает, система предлагает.

### Роли в демо

| Роль | Кто в демо | Что делает |
|---|---|---|
| Рекрутер | Анна Ковалёва | Вакансия, доска, отчёт, решение (передать менеджеру / запросить ещё / не продвигать) |
| Эксперт | Алексей С. | Рубрика и комплект (в демо только чтение), пилот: задачи, аудит, утверждение |
| Кандидат | Дмитрий / Никита / Лидия | Приглашение → согласие → проверка → правила → тренировка → 5 вопросов → готово |
| Менеджер | Игорь Матвеев | Короткий одностраничник перед встречей, без прокторинга |
| Админ | Ольга Белова | В спеке — доступы. В демо — карточка со **всеми вкладками** сотрудников, чтобы жюри не искало сиротские экраны |

На карточке рекрутера **нет процентов** и **нет единого балла**. Статусы словами: соответствует / не соответствует / недостаточно данных. «Недостаточно данных» всегда говорит, почему и что делать человеку. Камера **не обязательна** для оценки (проверка устройства ≠ условие скоринга). Прокторинг не влияет на технический вывод.

### Что в MVP демо

Одна вакансия **Middle+ Python**, 5 вопросов, моки в `frontend/lib/demo/`. Нет Huntflow, нет автоотказа, нет анализа лица. Часть маршрутов помечена **«Пилот»**: экран есть, часть кнопок — макет (тост или disabled).

Метрика пилота в каноне — **ДЗС**: доля скринингов, где рекрутер пошёл дальше без живого техинтервью **и** выборочный аудит не нашёл критичной выдумки.

### Тон интерфейса

Точный, спокойный, доказательный. Рабочий инструмент, не лендинг. Не градиенты, не «магический скор», не экзаменационный прокторинг на весь экран кандидата. AI-блок и решение человека визуально разделены (`AiNote` / `HumanNote`).

## 3. Как собран интерфейс

```
Браузер
  └── app/layout.tsx          единственный Next-layout
        ThemeProvider
        └── page.tsx          сама выбирает оболочку
              ├── AppShell              рекрутер / эксперт / менеджер / админ
              ├── CandidateShell        путь кандидата /i/…
              ├── BrandMark + header    вход, бриф
              └── голый workspace       403 / 404 / expired
```

Вложенных `layout.tsx` нет. Редиректы в коде: `/` → `/login`, `/interview/[token]` → `/i/[token]`.

| Каркас | Кто видит | Из чего состоит |
|---|---|---|
| **AppShell** | Сотрудник | Сайдбар 220px + топбар («К выбору роли», луна/солнце) + `<main class="workspace">` |
| **CandidateShell** | Кандидат | Логотип, вакансия, **степпер из 7 шагов**, контент ~720px, помощь (почта, Telegram, «К выбору роли») |
| **BrandMark only** | Вход, бриф | Без сайдбара |
| **Без оболочки** | 403, 404, истёкшая ссылка | PageHeader + кнопка во вход |

Nav задаёт страница: `recruiterNav` (Вакансии), `expertNav` (задачи, рубрика, комплект, аудит, утверждение), `managerNav` (встречи, Лидия), `adminNav` (все вкладки + доп. вопрос Лидии). Подсветка = самое длинное совпадение пути. У админа полный сайдбар показывается **после монтирования** (чтобы не сломать гидрацию).

**LaptopGate** (ширина ≤ 900px): вместо интервью — «Откройте с ноутбука». Стоит на проверке, правилах, тренировке, вопросах, уточнении, resume. На приглашении гейта нет.

### Где данные (сервера нет)

| Что | Где |
|---|---|
| Роли, попап, `homePath` | `frontend/lib/demo/roles.ts` |
| Вакансия Middle+ Python | `vacancies.ts` (`python-middle`) |
| Три отчёта | `candidates.ts` (токены `dmitry`, `nikita`, `lida`) |
| Семь карточек канбана | `pipeline.ts` |
| Рубрика и вопросы | `rubric.ts` |
| Выбранная роль | `sessionStorage` → `napoleon-demo-role` |
| Прогресс интервью | `sessionStorage` → `napoleon-candidate-session:{token}` |
| Приглашения и решения | `sessionStorage` → `napoleon-recruiter-store` |
| Тема | `localStorage` → `napoleon-theme` |

### 4.2 Рекрутер

#### R1 `/vacancies` — список вакансий

- **Файл:** `app/vacancies/page.tsx` · AppShell рекрутера
- Заголовок «Вакансии»; «Новая вакансия»; вкладки Активные / Черновики / На проверке / Архив.

- **Файл:** `app/vacancies/new/page.tsx`

#### R3 `/vacancies/python-middle` — доска / список

- **Файл:** `app/vacancies/[id]/page.tsx`
- Неизвестный `id` → «Вакансия не найдена».
- Шапка: путь, h1 «Кандидаты», статус Активна, «+ Пригласить», «⋯ Настройки».
- Подсказка: смотреть колонку «Отчёт готов».
- Тулбар: зелёная точка «Приём ответов открыт»; **Доска / Список**; VersionTag.
- **Доска:** 5 колонок `.kanban` — Приглашены, Проходят, Обработка, Отчёт готов, Решено. В карточке имя и статус словами; «Открыть отчёт» только если отчёт есть. Текста «отчёта ещё нет» нет.
- **Список:** те же люди, стадия подписана, колонка Отчёт = ссылка или «—».
- **R4 модалка приглашения:** имя, почта, превью письма, «Отправить» / «Скопировать ссылку» (`/i/{token}`), тосты.

#### R8 `/vacancies/[id]/settings` — настройки · **пилот**

- PageHeader + PilotBadge; блоки Общее / Версии / Письма (макет); «К доске».

#### R5 `/vacancies/[id]/candidates/[cid]` — технический отчёт

- **Файл:** `app/vacancies/[id]/candidates/[cid]/page.tsx`
- Нет кандидата → «Отчёт не найден».
- Шапка: Кандидаты / имя; h1 «Технический отчёт»; длительность, дата; VersionTag; **Кратко / Подробно**.
- Тело: AiNote (словами, без балла); у Лидии плашка «недостаточно данных»; три колонки сильные / риски / не проверено; прокторинг одной строкой (не влияет на оценку); слева карта требований, справа вывод + цитата (`EvidenceLink`).

### 4.5 Кандидат `/i/{token}`

Токены: `dmitry` | `nikita` | `lida`. Неизвестный токен → «Ссылка не найдена» + «К выбору роли».

#### C1 `/i/[token]` — приглашение

- Loading «Загружаю…», затем факты: ~25 мин, 5 вопросов, дедлайн; Как устроено; Можно / Нельзя / Устройство.

#### C2 `/i/[token]/consent` — согласие

- Запись; чекбоксы аудио (обязателен) и видео (по желанию); ящик с полным текстом (Drawer); Назад / Продолжить. Без аудио кнопка серая + hint «Отметьте согласие на запись аудио».

#### C3 `/i/[token]/check` — проверка устройства · LaptopGate

- Имитация записи 5 секунд, волны, чекбокс «только текст», статус соединения; «Всё работает» → правила.

#### C4 `/i/[token]/rules` — правила · LaptopGate

- Список 1–8; «Понятно, к тренировке»; иногда «Пропустить тренировку» → вопрос 1.

#### C5 `/i/[token]/practice` — тренировка · LaptopGate

- Не оценивается; запись тренировочного ответа; «К первому вопросу».

#### C6 `/i/[token]/q/[n]` — вопрос · LaptopGate

- Прогресс, формулировка, прослушать / переформулировать, таймер подумать + заметки, голос или текст, отправка. Пустой текст: disabled + «Сначала напишите ответ».
- Нет вопроса → «Вопрос не найден». После части вопросов — C7; в конце — `/done`.

#### C7 `/i/[token]/q/[n]/follow-up` — уточнение · LaptopGate

- Короткий follow-up, голос/текст. Если `followUpText` в данных пустой, заголовок: «Нужно уточнить один момент по этому ответу».

#### C8 `/i/[token]/resume` — продолжить после обрыва · LaptopGate

- «Продолжить интервью» → текущий номер из session.

#### C9 `/i/[token]/done` — отправлено

- «Интервью отправлено»; что будет сегодня / до даты / позже; ссылки: транскрипт, итог (пилот), **дополнительный вопрос (пилот)**, запрос удаления.

#### C10 `/i/[token]/extra/[id]` — доп. ответ · **пилот**

- Заглушка вопроса; запись disabled + «в пилоте это макет»; назад к done.
- Входы: админ-меню «Доп. вопрос (пилот)», done, отчёт после запроса доп. ответа.

#### C11 `/i/[token]/transcript` — транскрипт · заглушка

- «Позже»; назад к done.

#### C12 `/i/[token]/result` — итог для кандидата · **пилот**

- Бейдж Пилот; требования **названиями** (не id вроде `async`); решение рекрутера зашито; назад к done.

#### C13 `/i/[token]/request` — запрос удаления / пересмотра · **пилот**

- Переключатель, textarea, «Отправить» (локально «отправлено»).

### 5.2 Состояния кнопки

Общие правила в `product.css`:

- **default / hover / active:** primary, secondary, ghost, icon-button. Active: `translateY(1px)`. У text-button active нет.
- **focus-visible:** кольцо `--focus` у button, input, textarea, summary. У ссылок сайдбара кольца нет.
- **disabled:** `opacity: .42`, `cursor: not-allowed`. Отдельного `:disabled:hover` нет.
- **loading:** у `Button` нет. На «Извлечь требования» меняется только текст.

| Имя в коде | CSS | Смысл |
|---|---|---|
| `default` / `primary` | `.button--primary` | Главное, `--accent` |
| `secondary` / `outline` | `.button--secondary` | Рамка |
| `ghost` | `.button--ghost` | Тихая |
| `text` | `.text-button` | Текстовая команда |
| `size="large"` | `.button--large` | Высота 48px |

**`.disabled-hint` уже есть:** пригласить (в демо скрыт — вакансия Активна); согласие «Продолжить»; «Отправить ответ» на вопросе и follow-up; бриф «Назад» на шаге 0.

**Ещё без hint у самой кнопки:** комплект/рубрика/extra (есть общий `.pilot-hint`); «Переформулировать» после первого раза; «Голосом» при text-only; «Всё работает» пока нет записи; аудит «Сохранить» (рядом текст «Ответьте на первый вопрос»).

«Утвердить v2» **не** disabled: клик → тост.

### 5.3 Состояния экрана, модалки, тоста

| kind | Как выглядит | Где |
|---|---|---|
| **loading** | Сплошная рамка, «Загружаю…», без скелетона | Почти только приглашение C1 |
| **empty** | Пунктир + «в этом демо…» + действие | Вкладки вакансий кроме «Активные» |
| **error** | Пунктир, `role="alert"`, что/зачем/куда | Битый id/token |
| **ready** | Обычная страница | Всё остальное |

| Модалка | Esc | Крестик | Фон | Focus-trap |
|---|---|---|---|---|
| Modal | да | да | да | нет |
| EvidenceLink | да | да | да | нет |
| Drawer | да | да | да | нет |

Тост: нет кнопки закрыть, нет типов success/error, ключ React = текст сообщения (два одинаковых схлопнутся).

### 5.4 Чего в виджетах нет (и не баг продукта)

Нет: DnD канбана, скелетона сетки, tooltip, focus-trap, loading на кнопке, атома ошибки поля, command palette, графиков, аватаров и тегов на карточке, прогресс-бара «вопрос 3 из 5» (у Павла это текст `stageLine`). Процента на карточке **не должно быть** по канону.

## Как проверить глазами

1. Светлая/тёмная: рекрутер → луна в топбаре → обновить страницу (тема из `localStorage`).
2. `/login` → «Открыть» на карточках → попап эксперта «Открыть задачи» → `/expert`.
3. Клик по серому фону попапа закрывает его.
4. Админ Ольга → в сайдбаре «Доп. вопрос (пилот)».
5. Доска: 5 колонок, без фразы «отчёта ещё нет», без %.
6. Кандидат `/i/lida`: 7 шагов степпера. На ширине ≤900px после приглашения — LaptopGate.
7. Согласие без галочки аудио — серая «Продолжить» и подсказка.
8. Утверждение: клик «Утвердить v2» — тост справа снизу поверх шелла.

Автопроверка: `cd tools/live-view && node check-holes.mjs`.
