# Обзор экранов, 6 сентября 2026

Каталог всех экранов кабинета и кандидатского пути на текущем `main`.

| Файл | Зачем |
|---|---|
| `screens.html` | Открыть в браузере. Картинки лежат рядом в `screens/`. |
| `screens.pdf` | Тот же каталог одним файлом — удобно слать. |
| `screens/*.jpg` | Кадры 1440×900, снятые с моком API. |

Под каждым экраном подпись: что на нём видно. Зелёным — уже сделано на фронте. Жёлтым — без бэкенда не закрыть.

Через все роли проходит один снимок: вакансия Middle+ Python Developer, пять требований, пять вопросов. Лидия ждёт решения, Дмитрий передан менеджеру, Павел в интервью.

## Статус I1 (честность обещаний)

I1 убрал обещания, которые интерфейс не может выполнить: нет роли администратора, нет регистрации в основном ряду входа, нет «Написать рекрутеру», нет подстановки срока приглашения на доп. вопрос, «Ответ есть» не выдаётся за подтверждение навыка.

Проверено юнит-тестами: 401 на входе → «Не удалось войти. Проверьте почту и пароль»; пользователи без роли «Администратор»; наличие ответа ≠ подтверждение навыка; отказ камеры при рабочем микрофоне; локальная заметка не обещает письмо; срок приглашения не наследуется доп. вопросу; пустая колонка «Приглашены» не врёт, если люди уже дальше; ошибка буфера ≠ «скопировано».

С контрактом API пока нельзя закрыть: текст и срок доп. вопроса, разбор по требованиям на типе Interview, исход встречи менеджера, таймкоды и запись, сравнение версий рубрики, срок приглашения часто нет на живом бэкенде, слепок версии рубрики экран отчёта не использует. Восстановление сессии кандидата уже опирается на `product_state` — это не дыра I1.

Не проверяли вживую: системный запрос getUserMedia, живую комнату LiveKit, системный запрос на буфер обмена.

## Как пересобрать

Нужен запущенный фронт. Бэкенд не нужен: ответы API подменяются фикстурами.

```bash
cd frontend && npm run dev
cd tools/live-view && node build-catalog.mjs
```

Фикстуры — `tools/live-view/fixtures.mjs`.

## Как отдавать кадры агенту на ревью

Не кормить одним PDF. Агенту лучше:

1. `screens.html` — оглавление (роль, маршрут, подпись).
2. `screens/<id>.jpg` — один экран = один файл, смотреть картинкой, не через OCR PDF.
3. При сомнении — живой UI через `tools/live-view` и код маршрута.

`screens.pdf` — для людей, чтобы переслать каталог целиком.

Готовый промт ревью (суть продукта, роли, словарь, шаблон ТЗ, итерации): `design-review-prompt.md`.
