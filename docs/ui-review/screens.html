Эти задачи упираются в контракт API. Интерфейс под них не рисует фальшивый успех.

7

Упирается в бэкенд

  1. Текст и срок доп. вопроса. Ответ extra отдаёт id, status и extra_token. Текста вопроса и отдельного срока в этом ответе нет. Фронт не подставляет срок приглашения.
  2. Разбор по требованиям. На клиентском типе Interview нет разбора по требованиям. Фронт не подставляет фальшивый разбор.
  3. Срок приглашения на живом бэкенде. Срок часто отсутствует в ответе приглашения. Мок для экрана приглашения его отдаёт. Экран extra этот срок не наследует.
  4. Слепок версии рубрики в отчёте. Слепок версии в API есть, экран отчёта его не использует как разбор навыков.
  5. Исход встречи у менеджера. Нужна ручка записи исхода. Место на карточке есть, писать некуда. Кнопки «берём / нет» без сохранения не рисуем.
  6. Таймкоды и запись. Цитаты в отчёте станут кликабельными, когда в ответе появятся время начала и ссылка на запись. До этого плеер рисовать нечем.
  7. Сравнение версий рубрики. На утверждении нужен diff двух версий. Слепок требований в версии уже есть, сравнивать две версии должен сервер.
