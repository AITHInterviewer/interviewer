# Роадмап: рабочий продукт

Цель — не демо на моках. Цель — **тот продукт, который уже описан**: эксперт один раз задаёт стандарт, кандидат отвечает когда удобно, рекрутер решает по цитатам. Данные настоящие. Письма настоящие. Запись настоящая. Оценка по записи, не из выдуманного файла.

Как читать этот файл:

1. Сначала **один список по блокам** — это весь продукт.
2. Потом **Илья / Артур / Аня** — те же пункты, разложенные по людям.
3. Номера вроде `B3` — одна работа. Если она у двоих, делают вместе, не два раза.

Живые правила экранов и дыр: [`слепые-зоны-доработки.md`](слепые-зоны-доработки.md).  
Как продукт себя ведёт: [`artifacts/00-canon/PRODUCT_SPEC.md`](artifacts/00-canon/PRODUCT_SPEC.md).  
Тон интерфейса: [`artifacts/00-canon/PRODUCT.md`](artifacts/00-canon/PRODUCT.md).

На экране рекрутера **нет** процентов и единого балла. Цифры, если считаются внутри, наружу не показываем.

Не делаем в этом продукте: рейтинг кандидатов, автоотказ, анализ лица и эмоций, биометрию, полноценный live coding.

## Где продукт сейчас

Четыре куска лежат рядом и **не склеены**.

| Кусок | Сейчас | Надо |
|---|---|---|
| Сайт | Много экранов, люди и отчёты выдуманы | Те же экраны, данные с сервера |
| Сервер | Только «я живой» | Вакансии, люди, записи, отчёты, решения |
| Агент | Логика разговора в своей программе, сайт его не вызывает | Кандидат говорит → агент ведёт → лог и запись на сервере |
| Оценка | Формула вердикта есть, сама ничего не слушает | Берёт запись, ставит цитаты и статусы словами, отдаёт рекрутеру |

Пока сайт читает `frontend/lib/demo/` — это не продукт, это заготовка картинок.

## A. Склейка (без этого остальное театр)

Сейчас этого нет совсем.

- **A1.** Одна настоящая вакансия Middle+ Python в базе, не в моке.
- **A2.** Один настоящий кандидат проходит ссылку → ответы пишутся на диск → появляется отчёт.
- **A3.** Рекрутер открывает **этот** отчёт, не карточку из `lib/demo`.
- **A4.** Сильный / слабый / серый кандидат дают разное поведение на тех же правилах.
- **A5.** Сайт перестаёт быть источником правды. Моки выключаются.

Готово когда: можно выключить папку `frontend/lib/demo/` и путь не умирает.

## B. ИИ-агент (разговор)

Сейчас: граф пауз и уточнений работает в `live-agent`. Можно прогнать скриптом без микрофона. Живой голос end-to-end не прогоняли. Сайт не вызывает агента. Оценок во время разговора нет (так и должно быть).

- **B1.** Довести голос: микрофон → распознать речь → ответ агента в колонки. Сессия сама заканчивается, когда вопросы кончились.
- **B2.** Прогон с настоящим Claude, не только подставным мозгом.
- **B3.** Кандидат на сайте попадает в тот же разговор, не в фейк-кнопку «Записать».
- **B4.** Каждый ответ — отдельный кусок аудио/видео + кусок лога. Есть таймкоды.
- **B5.** Уточнения: не больше лимитов. Если обязательный навык не закрыт и время ещё есть — следующий вопрос из комплекта эксперта, не новый выдуманный. (Это SZ-19, ум агента.)
- **B6.** Кандидат может пропустить уточнение. Когда время окна кончилось — стоп, дыры честно едут в отчёт.
- **B7.** Лог одного интервью лежит там, откуда его заберёт оценка и сервер, не только в `live-agent/out/` на ноутбуке.
- **B8.** Позже, не в первом рабочем контуре: задача с кодом на экране, сверка с резюме.

Файлы: `live-agent/README.md`, `live-agent/CLAUDE.md`, `live-agent/src/ainterviewer/`, `live-agent/scripts/simulate.py`, `live-agent/mock_data/interview_example.json`, `specs/001-live-interview-contour/spec.md`.

## C. Оценка (после разговора)

Сейчас: `verdict.py` по готовым баллам считает класс. Воркер пустой. Цитат нет. На сайт ничего не приходит.

- **C1.** Вход: запись + лог агента + рубрика этой вакансии.
- **C2.** Хорошая расшифровка (термины вакансии не ломаются: celery, postgres и т.д.).
- **C3.** По каждому обязательному требованию: статус словами + цитата + таймкод. Если цитаты нет — «недостаточно данных», не выдумка.
- **C4.** Внутренняя формула вердикта может остаться. На экран идёт адаптер: слова, не проценты.
- **C5.** Серое (дыра в обязательном, смесь статусов) помечается так, чтобы карточка уехала **эксперту**, не рекрутеру «на глаз». (SZ-20)
- **C6.** Критическая ошибка: система предлагает «не продвигать», человек подтверждает, пишется заметка человека. Без подтверждения карточка не закрывается.
- **C7.** Прокторинг (вкладка, камера) — отдельная лента, не часть технической оценки.
- **C8.** Несколько прогонов модели не должны молча менять отчёт. Версия модели и рубрики пишется рядом с отчётом.

Файлы: `evaluation-agent/src/evaluation_agent/verdict.py`, `worker.py`, `specs/002-batch-evaluation-contour/spec.md`, `artifacts/00-canon/PRODUCT_SPEC.md` (карта доказательств).

## D. Сервер и хранение

Сейчас: `GET /health`. Postgres в Docker есть, таблиц в приложении нет.

- **D1.** Пользователи и роли: рекрутер, эксперт, кандидат по ссылке, менеджер.
- **D2.** Вакансия, список требований (один, не три разных), рубрика, комплект вопросов, версии.
- **D3.** Приглашение, сессия, ответы, файлы записи, транскрипт, отчёт, решение человека, заметка человека.
- **D4.** События: приглашение создано / открыто / брошено / интервью идёт / обработка / ошибка разбора / готово.
- **D5.** Файлы записи в нормальном хранилище, не на рабочем столе. Сроки хранения — закрыть до пилота (открытый вопрос спеки).
- **D6.** API, которым пользуется сайт. Без обходных моков в проде.
- **D7.** Запуск всего контура одной понятной командой, которая реально поднимается.

Файлы: корневой `README.md`, `docker-compose.yml`, `docker-compose.dev.yml`, `backend/app/main.py`, `backend/README.md`, `specs/002-docker-dev-baseline/`.

## E. Сайт — все роли, живые данные

Сейчас: экраны нарисованы. Часть — макет «потом». Данные фейк.

Общее для всех экранов:

- **E0.** Убрать выдуманных людей из рабочего режима. Пустые списки, ошибки сети, «идёт разбор» — настоящие состояния, не заглушки.

### Кандидат

- **E1.** Ссылка, согласие, проверка устройства. Камера не условие оценки, аудио+текст достаточно.
- **E2.** Правила: что оцениваем, что нет, можно ли документом, кто увидит запись.
- **E3.** Тренировочный вопрос. Потом настоящие вопросы и уточнения агента. Прогресс можно продолжить, если оборвалось.
- **E4.** Честное окно времени на первом экране. По окончании — «ответы получили», без карты «почему». Дальше статусы ожидания: смотрим до даты → ждите рекрутера. (SZ-01) Экран «разбор почему отказ» кандидату не делаем.
- **E5.** Редкая досылка одного вопроса, только если эксперт заказал. (SZ-03, C10)

### Рекрутер

- **E6.** Создать вакансию из описания. Один список требований. (SZ-05)
- **E7.** Нельзя выдать ссылку, пока эксперт не утвердил комплект. Статусы: черновик → на проверке → активна. (SZ-06)
- **E8.** К приглашению прикладывается уже известный профиль человека. Кандидата не просим рассказывать биографию заново. (SZ-16)
- **E9.** Пока почты нет в коде — нельзя писать «письмо ушло». Когда почта появится — «доставлено / открыто / не открыто». (SZ-02, SZ-08)
- **E10.** Канбан: проходят / обработка / ошибка разбора / готово. Зависший разбор не выглядит как «ещё отвечает». (SZ-07)
- **E11.** Очередь **ясных** отчётов. Серые сюда не мешать. Критическая ошибка сверху, подтверждение одной кнопкой. (SZ-11)
- **E12.** Карточка: статусы словами, цитата, таймкод, открыть исходный ответ. «Система предлагает» отдельно от «рекрутер решил». Передача менеджеру только руками.

### Эксперт

- **E13.** Очередь калибровки вакансий, дедлайн, «ждём N дней». (SZ-10)
- **E14.** Рубрика и вопросы на том же списке требований, что извлёкли из вакансии. Утверждение открывает инвайты.
- **E15.** Очередь серых отчётов: хватит / один точечный вопрос / оставить на встречу, если не стоп-фактор. Созвона с кандидатом нет. (SZ-20)
- **E16.** Отдельный аудит рубрики без имён — чинить критерий для следующих, не путать с очередью серых. (SZ-13)

### Менеджер

- **E17.** Одностраничник перед встречей. Блок «уже доказано, не переспрашивать». Прокторинга нет. «Ещё этап» — исключение с подписью. (SZ-14, SZ-15)
- **E18.** Ответ «берём / ещё этап / нет» возвращается в историю рекрутера. В оффер продукт сам не едет. (SZ-04, SZ-18)
- **E19.** Бриф менеджера до инвайта не обязателен и не ворота.

Файлы: `frontend/README.md`, `frontend/app/`, `specs/005-evidence-interview-ui/spec.md`, `specs/005-evidence-interview-ui/contracts/ui-routes.md`, `docs/audience-process-roadmap.html`.

## H. Качество, право, пилот

Сейчас не закрыто.

- **H1.** Сроки хранения видео / текста / отчёта. Человек всегда может пересмотреть решение. (спека, открытые вопросы)
- **H2.** Кто в Napoleon владелец рубрики, сроки кандидату, можно ли перезаписать ответ, какой фидбэк кандидату, как проверить личность без биометрии.
- **H3.** Считать на пилоте: рекрутер пошёл дальше без живого техинтервью; аудит не нашёл выдуманных цитат; менеджер не вернул человека за дыру в базе.
- **H4.** Словарь терминов вакансии в расшифровке.
- **H5.** После того как Middle+ Python живой: другие роли и грейды, библиотека рубрик, профиль навыков между вакансиями — это уже целевой продукт после пилота, не первый контур.
